# Pembaruan dan perbaikan 29 September 2026

## Penyebab foto leaderboard hilang

Pemeriksaan baca-saja pada Supabase menemukan satu foto leaderboard aktif berukuran 14 byte. Isinya adalah teks `File not found`, bukan data JPEG walaupun metadata server menyebut JPEG. File tersebut tidak dapat dipulihkan menjadi foto asli.

Alur baru membaca foto pada Android/iOS dengan Expo FileSystem, mengonversinya menjadi JPEG, memperkecil gambar, dan memvalidasi isi biner sebelum unggahan. Fetch untuk file lokal tidak lagi dipakai pada perangkat native. Foto profil, galeri, berita, dan event memakai alur yang sama.

Untuk memperbaiki foto lama: Profil > Panel pengelola > Galeri & juara > Peringkat > Edit data & foto > Ganti foto tangkapan > pilih foto asli > Simpan penimbangan. Foto yang sudah rusak perlu dipilih ulang satu kali. Data nama dan berat tidak dihapus.

## Perubahan aplikasi

- Komponen foto bersama: indikator memuat, penanda foto tidak tersedia, dan tombol memuat ulang untuk pratinjau besar. Tidak mengganti foto tangkapan yang rusak dengan foto orang lain atau gambar contoh.
- Filter peringkat Hari Ini dan Bulanan menggunakan WIB. Per Event mempunyai pilihan event sebenarnya. Kaitan event, jumlah ikan dan total berat dapat dicatat oleh pengelola.
- Panel komunitas mempunyai tab status galeri, pratinjau foto, validasi tanggal/berat, dan pencegahan kirim ganda.
- Halaman Kiriman Saya memperlihatkan status foto menunggu, disetujui, atau ditolak.
- Reservasi menunggu pembayaran tidak lagi dianggap tiket aktif pada profil. Statistik profil dan riwayat berasal dari akun yang masuk, bukan angka contoh.
- Inventaris admin: lapak kosong/ditahan/terjual, nama dan username pembeli, pencarian kode/nomor/nama, serta riwayat batal/kedaluwarsa. Diperbarui setiap 15 detik saat halaman aktif.
- Pemilihan lapak: tombol lebih besar, pilihan daftar/denah, tidak memakai lapak acak saat koneksi gagal, dan tidak mengizinkan lanjut sebelum data ketersediaan berhasil dimuat.
- Admin dapat mengganti foto slide/event, deskripsi, kapasitas, tanggal selesai lintas hari, dan status unggulan.
- Filter agenda bekerja; beranda/berita/galeri online tidak menyisipkan konten contoh saat data kosong atau koneksi gagal.
- QR tiket sekarang mengodekan kode booking sebenarnya. Ini QR identitas tiket, bukan QRIS pembayaran. Operator tetap harus mencocokkan status server melalui panel inventaris; memindai QR saja bukan bukti tiket valid.
- Navigasi bawah mengikuti area aman HP dan halaman admin tidak menjadi tab publik tambahan.
- Bug pratinjau web saat membaca sesi login diperbaiki; penyimpanan sesi perangkat tidak dijalankan pada rendering server. Form profil menunggu data akun dimuat sebelum dapat diedit.
- Status pembayaran diperiksa hanya saat halaman aktif; pesan kegagalan tidak menghilangkan status terakhir. Kedaluwarsa ditampilkan konsisten pada profil, pesanan, dan inventaris.
- Tiket membaca detail event milik booking, termasuk riwayat event selesai setelah migrasi. QR tidak ditampilkan ketika pengguna keluar atau validasi server gagal. Event dibatalkan meminta pengguna menghubungi pengelola.
- Slide beranda otomatis berhenti saat halaman ditinggalkan; deskripsi lengkap event mempunyai bagian khusus dan tombol bagikan sudah berfungsi.

## Terapkan satu migrasi baru

Migrasi ini disiapkan di project, tetapi belum dijalankan pada Supabase online. Migrasi lama yang sudah berhasil dijalankan tidak perlu dijalankan ulang.

1. Buka Supabase project pemancingan Anda > SQL Editor.
2. Buat query baru dengan tombol `+` agar tidak mengganti empat query lama.
3. Jalankan isi `supabase/migrations/202609290001_community_booking_maturity.sql`.
4. Pastikan berhasil, kemudian muat ulang aplikasi.

Migrasi menambahkan jumlah/total tangkapan, pembatalan reservasi yang memeriksa kepemilikan, penyelarasan kedaluwarsa, dan audit perubahan tanpa menduplikasi nama/nomor telepon. Bucket gallery menjadi private. Aplikasi menggunakan URL sementara: tamu hanya untuk foto disetujui, pengguna untuk kirimannya sendiri, dan pengelola untuk moderasi.

Jangan menjadikan gallery private secara manual sebelum aplikasi versi ini digunakan. Untuk aplikasi lama yang masih memakai public URL, foto galeri tidak akan terbuka setelah migrasi. Foto pending yang pernah diakses sebelum migrasi mungkin masih ada dalam cache perangkat lama; pengaturan private tidak dapat menarik kembali file yang sudah diunduh.

Tidak ada penghapusan akun, foto, atau booking pada migrasi ini. Status kedaluwarsa diselaraskan saat pemilik/pengelola membaca pesanan dan ketika booking baru dibuat, bukan melalui scheduler permanen.

## Jalankan dan uji

Jalankan Expo kembali dari folder React ini dengan `npx expo start --clear`. Paket Expo FileSystem, ImageManipulator, SVG dan QR sudah ditambahkan sesuai SDK project. Untuk development build/APK lama, lakukan build ulang bila modul native belum tersedia.

`npm run check` menjalankan pemeriksaan TypeScript, lint, dan tes regresi. Tes otomatis meliputi file rusak 14 byte, format gambar, URL media, tanggal valid, periode WIB, pemilihan event, dan status booking kedaluwarsa.

Uji di HP dengan dua akun berbeda:

1. Admin mengganti foto leaderboard yang rusak; buka halaman Juara dan tarik untuk menyegarkan.
2. Pengguna mengganti foto profil, keluar/masuk kembali, lalu memastikan foto tetap tersimpan.
3. Pengguna mengirim foto galeri; hanya ia dan pengelola dapat membukanya sebelum disetujui. Tamu harus bisa melihatnya setelah disetujui.
4. Uji menolak kiriman, filter peringkat, dan total tangkapan setelah migrasi.
5. Pilih event dengan kapasitas kecil; tombol lapak harus sesuai jumlahnya. Nomor dengan booking aktif tidak boleh hilang ketika kapasitas dikurangi.
6. Dua pengguna mencoba lapak yang sama. Hanya satu reservasi boleh berhasil.
7. Matikan koneksi saat memilih lapak; aplikasi harus menjelaskan kendala, bukan membuat data terisi acak.
8. Tunggu batas pembayaran lalu periksa profil, pesanan, dan inventaris. Reservasi tidak boleh dianggap tiket lunas.
9. Tamu/pengguna biasa tidak boleh membaca data pembeli atau audit pengelola melalui API.

## Batas rilis publik

Pemeriksaan awal pada sesi pengembangan ini: TypeScript dan lint lolos, 9 tes regresi lolos, dan export bundle Android berhasil. Ini bukan pengujian APK/HP atau bukti bahwa migrasi sudah aktif. Pratinjau web dapat membaca beranda dan klasemen dari Supabase; pengunggahan ulang foto memerlukan foto asli milik pengguna.

Audit dependency melaporkan 14 peringatan tingkat moderate pada dependency Expo/Router dan alat build, tanpa high atau critical pada pemeriksaan ini. Pembaruan otomatis yang menyarankan downgrade besar Expo tidak diterapkan karena berisiko mematahkan kompatibilitas SDK. Temuan harus ditinjau dan diselesaikan dengan versi yang kompatibel sebelum rilis.

Pengembangan ini belum berarti siap rilis publik. Payment gateway, verifikasi webhook pembayaran, pemeriksaan tiket masuk satu kali, notifikasi push, penghapusan akun permanen dengan persetujuan, dan pengujian beban/perangkat masih diperlukan. Migrasi/RLS harus diuji langsung pada Supabase setelah diterapkan. Jangan menjual tiket sebagai pembayaran otomatis sebelum gateway benar-benar aktif.
